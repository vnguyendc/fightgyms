# weekly SEO monitor

Run `sh ops/seo-monitor/run.sh` from this checkout. Python 3.11+ needs `google-api-python-client` and `google-auth`. Vercel CLI must be logged in to the FightGyms team. The Search Console service account needs access to `sc-domain:findfightgyms.com`; the key path is read from `~/.config/claude-seo/google-api.json` with a fallback to `~/.config/claude-seo/service-account.json` (`--key` overrides it). No credential values belong in the repository.

The collector only reads Search Console, Vercel and public pages. Each source fails independently: an error means unavailable, never zero. A successful Search Console query omits dates with no activity; those dates alone are filled with zero. The reporting window ends three days ago to avoid incomplete Search Console days. Vercel uses the same completed UTC date bounds; its raw query metadata is retained. Vercel metrics are filtered to production and the `www.findfightgyms.com` and apex `findfightgyms.com` hostnames (the SDK historically records apex traffic). Top pages/queries compare 7-day windows. Daily search data spans two 28-day windows; Vercel spans 28 days. LCP uses p75. Empty LCP/metric summaries mean no recorded measurement, not a passing performance score.

A fixed URL Inspection sample is selected on the first successful run and reused in later bundles, including URLs subsequently dropped from the sitemap so deindexing stays observable. The first run favors historical demand and stratifies gym/city/discipline pages. All data is public directory/search aggregate data. `bundle.json` files are timestamped under `~/.local/share/fightgyms/seo-monitor/`. Weekly notes go to the real `VinhVault-AI/SEO Reports` folder. `--output`, `--vault`, and `--no-notify` support isolated verification; the vault must already contain `SEO Reports`. Exit 1 means an alert fired, not that successful source data was discarded.

Install with `sh ops/seo-monitor/install.sh`, remove with `sh ops/seo-monitor/uninstall.sh`. It runs Mondays at 08:10 in the Mac's local timezone (use America/New_York). Installation points at this exact checkout; keep it available or reinstall from a permanent checkout after merge. Logs: `~/Library/Logs/fightgyms/seo-monitor.{log,err}`. Check with `launchctl print gui/$(id -u)/com.vinh.fightgyms-seo-monitor`; trigger once with `launchctl kickstart gui/$(id -u)/com.vinh.fightgyms-seo-monitor`.

Tests: `python3 -m unittest discover -s scrapers/tests -p test_seo_monitor.py`. The script reports metric/auth failures; it never changes analytics settings or asks for broader credentials. Check the bundle's source errors and refresh the existing narrow credentials when necessary. Manual Actions still requires a separate UI check; URL Inspection and metrics do not certify its absence.

Notifications appear on the first run and when the alert set changes; unchanged routine results remain quiet. The installer pins the Python executable that installed the job, avoiding launchd PATH differences.
